## Highlights

- **One workspace for PR assistance.** Start with the task you want to do,
  keep explanations and follow-up questions together, and review with a
  concrete focus. Fix progress and results stay close to the PR; video is an
  alternate output. Findings remain private until you select and confirm the
  exact comments and posting target.
- **Clearer ARM and Bicep explanations.** Read Before/After examples,
  highlighted changes, benefits and risks grounded in the inspected revision.
  Follow-ups can carry the completed explanation or a selected section, with
  coverage limits disclosed instead of silently dropping context.
- **Compare a reference PR.** Supported Azure DevOps PR links provide separate,
  revision-pinned reference context for focused reviews. Access or context-size
  failures are explicit; a reference never changes where comments are posted.
- **New reviews and Fix runs are Windows-native.** Questions and focused
  reviews read pinned Azure DevOps source without WSL or a local checkout.
  New Fix runs use an owned worktree from your configured Windows Git checkout
  and the full Windows Copilot CLI. A separate, versioned supervisor keeps
  active run files independent of dashboard upgrades; retained legacy WSL runs
  keep their original backend and recovery controls.
- **Sign-in guidance that matches the app.** Explain, questions and focused
  reviews need the Windows GitHub CLI signed in with a Copilot-enabled account.
  VS Code and standalone `copilot login` do not supply that bundled runtime's
  sign-in. New Fix runs instead use the chosen Windows Copilot CLI's own
  authentication. The new troubleshooting guide explains the distinction.

## Upgrading and setup

Installed v0.1.4 copies can check for this release in Settings; portable copies
use the release-page download. v0.1.3 and earlier require a manual upgrade.
For new Fix runs, configure an existing absolute checkout path under
**Settings > Copilot on Windows**, install Git for Windows and a compatible
full Windows Copilot CLI, and authenticate that CLI before starting a run.
There is no automatic WSL fallback for new runs.

## Privacy and validation boundaries

Selected PR/source and reference context is sent to Copilot. Fix runs with broad
permissions, can execute repository instructions and is not a sandbox; reviewing
source does not grant Fix permission or publish comments automatically.

Offline fixtures cover pinned source, context handoff, private comment selection,
native run ownership and legacy recovery. Synthetic process and app-replacement
checks cover supervisor reconnect and exact Stop, but do not establish unrestricted
detached-job breakaway on every Windows host. Hosts that reject it fail explicitly.
Live CLI authentication, model reasoning, tenant permissions and native DPI remain
unverified. Disposable Windows CI covers packaging and installer paths; installers
remain unsigned.

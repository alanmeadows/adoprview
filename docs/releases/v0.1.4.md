## Upgrading from v0.1.3

v0.1.3 predates the in-app updater, so it cannot offer this release. Install
v0.1.4 manually with the installer or ZIP. Later releases can then be offered
through the updater on installed copies.

## Highlights

- **All now means all.** Previously, a fresh install showed the same PRs in All
  as in Mine because unwatched authors were dropped. All now covers active and
  completed PRs from every author in your added repositories. Mine shows your
  own PRs, and Mine + watched shows yours plus those of watched authors.
- **Watch list has a clearer role.** It scopes alerts and automatic merge
  rechecks; it no longer limits All. If you already had a nonempty watch list
  and no saved view, the view starts on Mine + watched. Result caps are shown
  when they apply.
- **Repositories are checked before saving.** Manually added repositories are
  validated against Azure DevOps first. On error, your typed input is kept, and
  a 404 is not reported as definitely missing when it may be inaccessible.
- **In-app updates.** ADO PR View checks for updates at startup, every 12 hours
  and on demand from Settings. Newer stable releases trigger a notification.
  Installed copies can download the installer, verify its size and SHA-256, and
  hand off and relaunch after you confirm. Portable and development builds link
  to the release page instead. Running supervised Copilot work survives the
  update and reconnects.

## Validation boundaries

Installers are unsigned. Release checks cover offline native tests and a
disposable Windows runner exercising synthetic data and installer paths. They
do not validate against a live Azure DevOps organization or measure API cost on
large repositories. Downloading a live GitHub release into the installer
handoff will not be exercised until a newer real release exists. Mine + watched
inclusion and exclusion has native marking coverage but no direct UI test.

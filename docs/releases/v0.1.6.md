## Highlights

- **Required pipeline failures get priority.** Expanded PR rows lead with
  failures that block completion. Optional failures remain available as
  secondary cards, clearly labeled nonblocking, with on-demand logs and the
  original policy's re-queue action.
- **Fix gets clearer diagnostics.** Required failures lead the prompt.
  Optional failures are listed separately, without automatically fetching
  their log tails, so advisory failures do not distract from required work.
- **Cached results keep the right policy context.** Display names and
  requiredness stay tied to each policy evaluation, including evaluations
  that share a build. Missing or null requiredness remains unknown rather
  than being guessed from a name.

The existing lane rules already ignored optional policies when determining
required-policy status. This release improves failure cards and Fix diagnostics;
it does not change Needs Human / Waiting / Blocked precedence.

## Upgrading

Installed v0.1.4 and v0.1.5 copies can check for this release in Settings.
Portable copies use the release-page download; v0.1.3 and earlier need a manual
upgrade.

## Validation boundaries

Offline native and synthetic browser checks cover required/optional policy
combinations, cached diagnostics and unknown requiredness. Live Azure DevOps
compatibility was not exercised, and this release does not establish that live
PoP sign-in issues are resolved. Disposable Windows CI covers packaging and
installer paths. Installers remain unsigned.
